# 试题质量预检工作台

课题“基于生成式人工智能的人机协同试题质量预检机制研究”的配套工具。流程：命题 → AI 预检 → 专家复核 → 试测验证 → 入库。

- **AI 预检**：按九项阅读认知属性标定每道题考查的属性，预估难度，检查答案唯一性、干扰项质量、超纲与偏题风险。
- **专家复核**：逐项采纳或修改 AI 意见，实时计算人机一致性（Cohen's Kappa），给出通过、修改或退回结论。
- **试测验证**：导入学生作答数据，对比 AI 预估难度与实测正确率，用 DINA 模型的题目区分度检验 Q 矩阵标定。

题组、预检结果、复核结论和作答数据都保存在服务器的 `data/sets.json` 里，所有访问者共用一份。

## 运行

需要 Node.js 20.12 以上，没有其他依赖。

```bash
cp .env.example .env     # 然后在 .env 里填 AI_API_KEY
node server.js           # 本机访问 http://localhost:8787
```

不填密钥也能运行，只是不能实时预检，只能查看示例题组和已有结果。

## AI 接口

使用 OpenAI 兼容格式，默认 DeepSeek。在 `.env` 里配置：

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `AI_API_KEY` | 接口密钥 | 空 |
| `AI_BASE_URL` | 接口地址 | `https://api.deepseek.com` |
| `AI_MODEL` | 模型名 | `deepseek-chat` |

改完 `.env` 需要重启服务。

## 远程访问

运行 `./start.sh`，它会启动服务并打印两种地址：

- **局域网地址** `http://本机IP:8787`：与这台电脑在同一网络（同一个 Wi-Fi、同一校园网段）的人可以直接访问。由 `.env` 里的 `HOST=0.0.0.0` 控制。
- **公网地址** `https://….trycloudflare.com`：需要先把 [cloudflared](https://github.com/cloudflare/cloudflared/releases) 放到 `bin/cloudflared`，并且当前网络能直连 Cloudflare。这个地址每次启动都会变。

电脑休眠、关机或关闭终端后，两种地址都会失效。工具没有访问口令，能打开链接的人都能查看和修改数据，所以服务端对 AI 调用做了限流（`RATE_PER_IP_HOUR`、`RATE_GLOBAL_DAY`）。

如果公网链接建立失败：在开着代理软件（如 Clash）的电脑上，cloudflared 的 DNS 查询常被拦截。可以换一个网络再试，或改用需要注册账号的国内内网穿透服务（cpolar、natapp 等），把它指向 `http://localhost:8787` 即可。

## 数据格式

**新建题组**时，试题按下面的格式粘贴：

```
1. 题干
A. 选项
B. 选项
C. 选项
D. 选项
答案：B
```

**作答数据**每行一名学生，列数等于题数，填 `1/0` 或学生所选的 `A–D`；最前面可以多一列学号，表头行自动跳过。

## 文件

| 文件 | 内容 |
| --- | --- |
| `server.js` | 服务端：静态页面、数据存取、AI 预检接口 |
| `public/` | 前端页面和脚本 |
| `framework.json` | 九项属性定义、预检维度、前期测验难度区间 |
| `seed/demo.json` | 示例题组（原创示例题，作答数据为模拟） |
| `data/` | 运行时数据，不提交到 Git，注意自行备份 |

九项属性的名称取自段惠琼《基于认知诊断的大学英语阅读障碍及其教学补救措施研究》，`framework.json` 中的编号顺序和释义是工作表述，以专著为准。
